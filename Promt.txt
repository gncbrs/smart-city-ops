### **9. Architecture & Design Decisions**
- **Requirement:** Explain *why* things were built this way, not just *what* was built.
- **Suggested subsections:**
  ```
  #### Clean Architecture Layering
  The backend strictly enforces dependency inversion: Domain layer has zero framework references, allowing entities and business logic to be tested independently of EF Core or HTTP concerns. This is verified in the latest codebase audit (no EF/Infrastructure refs found in Domain or Application projects).
  
  #### Concurrency Safety
  Field-unit task assignment uses a database-level partial unique index (one active task per unit) combined with a pessimistic lock-and-retry loop. This closes the classic "both requests read Available, both dispatch" race condition at the transaction level, with the database guaranteeing atomicity.
  
  #### Real-time Synchronization
  SignalR broadcasts operational updates (new incidents, task completions, field-unit status changes) to all connected clients. The frontend's TanStack React Query integration automatically invalidates and refetches affected queries on each server notification, keeping the UI in sync without polling.
  
  #### Fixed, Non-Scrolling Layout
  The operations dashboard intentionally uses a fixed (viewport-filling) layout with three pinned panels at the bottom. This mirrors physical NOC (Network Operations Center) design, where operators never scroll — every mission-critical piece is always visible.
  
  #### Priority Scoring
  Incident priority is computed server-side once and exposed on every `IncidentDto`, combining base severity (Incident.Priority enum) with an age bonus (up to +30 for incidents older than ~30 minutes). This is a single source of truth, preventing frontend/backend divergence.
  
  #### Ankara Zone Data
  Operational zone definitions (12 districts) are centralized in `SmartCityOps.Domain/Geography/AnkaraOperationalZones.cs`. Both the API endpoints and the incident generator reference this same static list, ensuring consistency across the platform.
  ```
- **Tone:** Each subsection should answer "what" and "why" together, addressing a non-obvious design choice.

  ```
  #### Real-time Synchronization via SignalR
  The backend's `OperationsHub` broadcasts notifications on domain events. The frontend's `useSignalR.ts` hook listens for `OperationsUpdated` and automatically invalidates the affected React Query cache keys:
  
  - **New incident** → invalidate `incidents`, `operational-zones`, `operations-statistics`, `replay-time-range`

  - **Restricted zone created** → invalidate `restricted-zones`
  - **Field unit status change** → invalidate `field-units`, `operational-statistics`
  
  This keeps all UI panels (map, incident list, task list, statistics) in sync without manual refresh and without polling overhead.
  ```
